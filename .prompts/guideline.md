# Coding Agent Guidelines

## リポジトリの目的

このリポジトリはアイデアを検証するためのサンドボックスです。各プロジェクトで異なるアイデアの開発環境を作成し、Coding Agent によって実装・検証を行います。アイデアが成熟した際に新たなリポジトリに分離できるよう、各プロジェクトは自己完結型として開発します。

## 基本原則

- 自己完結性: 各プロジェクトは独立して動作し、他のプロジェクトに依存しない
- 将来の分離可能性: プロジェクト内容を新しいリポジトリにそのまま移動できる構造を持つ
- 完全性: 各プロジェクトには実行、テスト、ドキュメント化に必要な全てのファイルを含める
- 品質保証: 実装する前に要件を明確化し、テスト可能な形で実装する

## 作業手順

### 1. 新しいプロジェクトの実装開始時

```
新しいプロジェクト「[プロジェクト名]」の実装を開始します。

1. プロジェクトを作成: `mkdir projects/[プロジェクト名]`
2. プロジェクトに移動: `cd projects/[プロジェクト名]`
3. 必要な基本ファイルを作成:
   - README.md (プロジェクトの説明、セットアップ、使用方法、テスト実行手順)
   - .gitignore (適切な除外設定)
   - app/ (実装ファイル)
   - docs/ (必要に応じてドキュメント)
   - docker-compose.yml (実行環境定義ファイル)
```

### 2. 実装中の作業方針

- 現在のプロジェクト内でのみ作業: `cd projects/[プロジェクト名]` 後、そのディレクトリ内で完結
- 相対パスの使用: 他のディレクトリへの絶対パスは使用しない
- テストの作成: 実装と同時にテストを作成し、動作確認を行う
- 一時的にファイルを書き出す際は.tmp ディレクトリを作成し、不要になったら削除する。

### 3. プロジェクトの成熟度評価

プロジェクトアは以下の基準で評価します：

- [ ] 基本機能が実装済み
- [ ] テストが作成され、全て通る
- [ ] ドキュメントが整備済み
- [ ] 外部依存関係が最小限
- [ ] 独立したリポジトリとして機能可能

## ディレクトリ構造テンプレート

```
[プロジェクト名]/
├── .devcontainer/
│   ├── Dockerfile          # 必要に応じて
│   ├── devcontainer.json   #
│   └── docker-compose.yml
├── docs/                   # 追加ドキュメント（必要に応じて）
│   ├── requirements.md     # 要件定義書
│   ├── design.md           # 技術設計書
│   └── tasks.md            # 実装計画
├── [Dockerサービス名]/       # メインの実装ファイル
│   ├── src/                # テストファイルは実装の近くに配置する
│   └── [その他のファイル]
├── .gitignore              # 適切な除外設定
├── .env.template
├── docker-compose.yml
├── Dockerfile              # Docker公式イメージのみ利用する
├── README.md               # プロジェクトの説明、セットアップ、使用方法、テスト実行手順
└── scripts/                # ビルド・デプロイスクリプト（必要に応じて）
```

## 実装時の具体的な指示

### コード品質

- 可読性: コードにコメントを適切に追加
- モジュール性: 機能ごとにファイルを分離
- エラーハンドリング: 適切なエラー処理を実装
- 型安全性: 型定義を充実

### テスト

- 単体テスト: 各機能の単体テストを作成
- 統合テスト: 必要に応じて統合テストを作成
- テストカバレッジ: 主要機能のテストカバレッジを確保

### ドキュメント

- README.md: プロジェクトの背景、セットアップ、使用方法を明記
- 要件定義書(requirements.md)
- 技術設計書(design.md)
- 実行計画書(tasks.md)

## 分離準備のチェックリスト

プロジェクトが成熟し、独立リポジトリに分離する準備ができた場合：

- [ ] 全ての依存関係が記載済み
- [ ] ディレクトリ内のファイルのみで動作確認済み
- [ ] CI/CD 設定ファイルが含まれている（.github/workflows/等）
- [ ] ライセンスファイルが含まれている
- [ ] 貢献ガイドラインが含まれている（必要に応じて）
- [ ] セキュリティポリシーが含まれている（必要に応じて）

この指示に従うことで、各プロジェクトが自己完結型で開発され、将来的に独立したリポジトリとして分離可能な状態を維持できます。
